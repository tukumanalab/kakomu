# kakomu

**[青学つくまなラボ](https://sites.google.com/view/tukumanalab/)のための、アクリルスタンド／アクリルキーホルダー制作ツール。**

好きな絵や写真を置き、それを囲む線をつくり、レーザー加工機と UV プリンターに渡します。Windows / macOS / Linux（omarchy を含む）で動きます。

- サイト: https://tukumanalab.github.io/kakomu/
- 設計仕様: [SPEC.md](SPEC.md)

> **状態: M0（基盤）・M1（書き出し）・M3（背景を消す）まで実装済み。**
> 画像を置いて動かし、ボタン 1 回で背景を消し、切るデータ（SVG）と印刷するデータ（PDF）を
> まとめて書き出せます。切る線の自動生成（M4）はまだで、いまは板の外形を仮に書き出します。

**出力先の機材**（実機に合わせて仕様を決めています）

| | |
|---|---|
| レーザー加工機 | xTool P3（XCS） |
| UV プリンター | Roland VersaSTUDIO BD-8（VersaWorks 7、白インクあり） |

## 入れかた

> **配布はまだ準備中です。** タグを打つと 3 OS 分のインストーラが
> [Releases](https://github.com/tukumanalab/kakomu/releases) に出るようにしてあります。
> それまでは下の「ソースから動かす」を使ってください。

コード署名をまだ入れていないので、どの OS でも初回に警告が出ます（SPEC 10.3）。

### Windows

`.msi` を実行します。「WindowsによってPCが保護されました」と出たら、**「詳細情報」→「実行」**。

### macOS

`.dmg` を開いて Applications に入れます。初回は「開発元を確認できないため開けません」と出るので、
アプリを **右クリック →「開く」** で起動してください。2 回目以降はそのまま開けます。

### Linux（一般）

```sh
chmod +x kakomu_*.AppImage
./kakomu_*.AppImage
```

### omarchy（Arch Linux + Hyprland）

kakomu は Wayland / Hyprland を主要な対応対象にしています。
Arch では **AUR パッケージを使うのがいちばん簡単**です。依存パッケージが一緒に入るので、
下で説明する落とし穴を踏みません。

```sh
yay -S kakomu-bin
```

> AUR への登録はまだです。それまでは、このリポジトリから直接ビルドできます。
> やることは同じで、依存も一緒に入ります。
>
> ```sh
> git clone https://github.com/tukumanalab/kakomu.git
> cd kakomu/packaging/aur/kakomu-bin
> makepkg -si
> ```

#### AppImage を手で入れる場合

依存を自分で揃える必要があります。

```sh
sudo pacman -S --needed \
  webkit2gtk-4.1 gtk3 librsvg \
  xdg-desktop-portal xdg-desktop-portal-gtk xdg-desktop-portal-hyprland \
  fuse2

chmod +x kakomu_*.AppImage
./kakomu_*.AppImage
```

| パッケージ | なぜ要るか |
|---|---|
| `webkit2gtk-4.1` `gtk3` `librsvg` | 画面の描画。無いと起動しません |
| `xdg-desktop-portal` **と** `xdg-desktop-portal-gtk` | ファイルを開くダイアログ。kakomu は portal 越しにダイアログを出し、**その実体を持っているのが `-gtk`** です。入れ忘れると「絵を入れる」を押しても何も起きません |
| `xdg-desktop-portal-hyprland` | Hyprland で portal を正しく振り分けるため。omarchy では入れておきます |
| `fuse2` | AppImage の実行に要ります |

**画面が真っ白になる／描画が崩れるとき**は、WebKitGTK の DMABUF レンダラを切ってください。
Nvidia ドライバや一部のコンポジタで起きます。

```sh
WEBKIT_DISABLE_DMABUF_RENDERER=1 ./kakomu_*.AppImage
```

毎回付けるのが面倒なら、`~/.config/environment.d/kakomu.conf` に書いておけます。

```
WEBKIT_DISABLE_DMABUF_RENDERER=1
```

#### ソースからビルドする（Arch）

```sh
cd kakomu/packaging/aur/kakomu
makepkg -si
```

パッケージの定義は [`packaging/aur/`](packaging/aur/) にあります。
`depends` は Cargo の機能構成から決めたもので、**実機ではまだ確かめていません**。
起動しない場合は `ldd /usr/bin/kakomu | grep 'not found'` で不足を調べて追加してください。

## 動かす

```sh
pnpm install
pnpm app      # アプリを起動する（tauri dev）
```

その他:

```sh
pnpm check    # 型検査
pnpm test     # 単体テスト（読みやすさ 2 段階のキー網羅を含む）
pnpm build    # フロントエンドのビルド
cd src-tauri && cargo test   # コアの単体テスト
```

### いま動くこと（M0）

- 画像の取り込み（PNG / JPEG / WebP / TIFF）。**画像の解像度を読んで実寸 mm を決める**（無ければ 350dpi と仮定）
- 移動・拡縮・回転。Shift で軸固定・比率維持・15度スナップ
- ズームとパン。ホイールで移動、⌘ + ホイールで拡大縮小
- 数値入力（すべて mm と度。**ピクセルは UI に出さない**）
- かんじ／ひらがなの切り替え
- もどす／やりなおす（ドラッグ 1 回が undo 1 回になるようまとめる）
- 実効解像度が 300dpi を下回ったときの警告

### 背景を消す（M3）

- ローカルの ONNX モデルで自動切り抜き。**画像を外部に送信しません**
- モデルは 3 つから選べます

  | UI 上の名前 | モデル | サイズ | 用途 |
  |---|---|---|---|
  | はやい | `u2netp` | 4.4MB | 既定。初回でも数秒 |
  | きれい | `isnet-general-use` | 170MB | 写真向け |
  | イラスト向け | `isnet-anime` | 168MB | 手描き・キャラクター |

- モデルは初回使用時にダウンロードします（進捗を表示）。ラボの共用 PC には事前配置します
- **非破壊**: 元画像は残り、「もどす」で戻せます。モデルを変えて何度でもやり直せます
- 「消す前と見くらべる」で切り替えて確認できます

### 書き出し（M1）

「書き出す」で、フォルダを選ぶと **2 つのファイルが同時に**出ます。片方を忘れる事故を防ぐためです。

| ファイル | 中身 | 持っていく先 |
|---|---|---|
| `<名前>_切る.svg` | 切る線。実寸 mm・マゼンタ・`fill="none"`・三次ベジェのみ | レーザー加工機 xTool P3（XCS） |
| `<名前>_印刷.pdf` | 絵柄。原寸・最大 600dpi・透過は SMask で保持・TrimBox / BleedBox 付き | UV プリンター Roland BD-8（VersaWorks 7） |

書き出したあと、どちらをどの機械に渡すかを画面に出します。

- **切る線をまだ作っていないので、いまは板の外形（角丸長方形）を仮に書き出します。** 実寸と色が加工機で正しく解釈されるかを、M4 の前に確かめられるようにするためです
- 白版は VersaWorks が自動生成するので、アプリでは作りません
- PDF はライブラリを使わず自前で書いています。箱（TrimBox / BleedBox）と配置行列を正確に制御するためで、macOS の PDF レンダラで配置と透過を検証済みです

## なにをするツールか

つくまなラボでは今 Inkscape を使っています。Inkscape は強力な汎用ドローツールですが、この作業をするには「ビットマップのトレース」「アウトセット」「ノード編集」を順に使う必要があり、設定項目も専門用語も多い。初等部の子に渡せる導線ではありません。

kakomu は Inkscape を置き換えるものではなく、**そこにあるワークフローのうちこの 1 つだけ**を取り出して、初等部の子から教職員までが使えるように作り直したものです。

```
1. 絵を入れる
2. 「うしろを消す」    … ローカル AI モデル。画像を外部に送信しない
3. 「囲む」            … 絵の 3mm 外側に、切るための線ができる
4. 点をドラッグして形を整える
5. 部品をつける        … キーホルダーなら φ4mm の穴、アクスタなら台座
6. 「かきだす」        … 切るデータ .svg ＋ 印刷するデータ .pdf
```

### 成功条件

> 初等部の子が、スタッフの短い声かけだけで、1 回の来室（13:00〜18:00 のうち）にアクリルキーホルダーを 1 つ完成させられること。

これが唯一の成功条件です。上級者向けの機能は、この条件を壊さない範囲で足します。

## 設計の柱

| | |
|---|---|
| **1 つの画面で、小 1 から教職員まで** | 子ども用の画面を別に作りません。ボタンの位置も機能も同じまま、**かんじ／ひらがな**を切り替えます。ひらがなは機械変換ではなく人が言い換えを書き下ろします（※ 現在は機能の実装を優先し、切り替えを UI から外して漢字モードのみで動かしています。文言と仕組みは残してあります） |
| **座標系はすべて mm** | UI にピクセルを出しません（例外は実効解像度の dpi 表示のみ）。加工機に渡すデータで最も事故が起きるのが単位系です |
| **切れない形を作らせない** | 最小幅 1.5mm・最小穴径 φ2mm・自己交差・鋭角を自動チェックし、**なぜダメかとどう直すか**をセットで出します。エラーは門番ではなく教材です |
| **破壊的な操作を作らない** | 背景も切る線も元データを消さず、元画像は `.kkm` 内に無改変で残ります。戻れると分かっていれば試行錯誤できます |
| **オフラインで完結** | AI 推論はすべてローカル。未成年が使うため、画像を外部に送信しません |

## 用語について

このリポジトリでは **「入稿」という言葉を使いません**。入稿は外部の印刷業者にデータを渡す行為を指す言葉で、加工機が同じ部屋にあるファブスペースの体験とずれるためです。

| 使わない | 使う |
|---|---|
| 入稿データ | 加工データ／切るデータ・印刷するデータ |
| 入稿する | 加工機に渡す／出力する |
| 業者 | ラボ／加工機 |

UI に出す言葉はさらに噛み砕きます。対応表は [SPEC.md の 3.4](SPEC.md#34-用語の対応表) を参照してください。

## 技術スタック

- **アプリシェル**: Tauri v2
- **フロントエンド**: TypeScript + Solid.js（キャンバスは SVG DOM）
- **コア**: Rust — `kurbo` / `clipper2`（ジオメトリ）、`ort`（ONNX 推論）、`printpdf`（PDF 生成）
- **同梱**: 背景除去モデル（`u2netp`）、UD フォント（BIZ UDGothic / Zen Maru Gothic）
- **配布**: MSI / NSIS・dmg（Universal）・AppImage・AUR

詳細と選定理由は [SPEC.md](SPEC.md) を参照してください。
